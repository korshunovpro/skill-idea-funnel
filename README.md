# idea-funnel

Скил для ИИ-агента, который не даёт проскочить разбор идеи.

Вы приносите замысел в том виде, в котором он лежит в голове. Агент вопросами доводит его
до картины, по которой видно реальность: кому это нужно на самом деле, что именно вы
делаете, вытянете ли своими силами, как результат дойдёт до людей. На выходе — основание
для плана или обоснованный отказ.

Центральная вещь здесь — сам скил, файл
[`skills/idea-funnel/SKILL.md`](skills/idea-funnel/SKILL.md); в нём весь метод. Рядом
лежит рабочий процесс, поэтому скил работает сразу после установки: агент знает не только
как разбирать идею, но и куда всё записывать. README — помощник: что в репозитории лежит,
зачем это и как поставить.

## Что в репозитории

| Файл | Что это |
|---|---|
| `skills/idea-funnel/SKILL.md` | сам скил: метод разбора идеи |
| `skills/idea-funnel/PROCESS.md` | учёт по умолчанию: статусы и гейты, скоринг, стоп-условия, заморозка |
| `skills/idea-funnel/templates/` | заготовки файлов идеи и воронки — агент раскладывает их сам |
| `AGENTS.md` | инструкция агенту: где лежит скил и куда его ставить |
| `README.md` | этот файл: что здесь лежит, кому это надо, как поставить |
| `CHANGELOG.md` | что менялось в методе от версии к версии |

Метод и учёт разведены намеренно: `SKILL.md` отвечает на «как разбирать идею»,
`PROCESS.md` — на «как её вести». Метод общий для всех, процесс у каждого свой, и
обновление скила из репозитория не затирает ваши статусы и пороги.

**Версия:** 0.3.0 · **Язык:** русский · **Лицензия:** MIT

## Кому это

Два узнаваемых случая.

**Идея не двигается.** «Да, надо бы это сделать» живёт месяцами. Не лень: непонятно,
с какого конца браться, а неопределённость выглядит необъятной.

**Идея превратилась в план, которым нельзя пользоваться.** Спросили у ИИ «хочу делать X» —
получили десять пунктов. В них не разобрано, кто клиент, есть ли у него боль, чего ради он
сменит поведение и кто за это платит. План выглядит убедительно, а вопросы, которые не
задали, всплывают через месяц — уже как разочарование.

Скил закрывает оба: он ведёт разбор, а не выдаёт план.

## Что будет на выходе

Один связный разговор, после которого у вас есть:

- кому это нужно и что у этого человека болит — на его языке, а не «это всем нужно»;
- чего ради он изменит поведение, и изменит ли вообще;
- в какой форме результат до него доедет и что в эту форму не входит;
- где самое трудное место и чем его дёшево проверить;
- проверяемый критерий успеха со сроком;
- решение: делаем, проверяем или не делаем.

Отказ здесь — нормальный результат, ради которого всё и затевается: после него остаётся
понимание, почему нет, и не потраченные на это месяцы.

## Чего ожидать от разговора

- это диалог, а не выдача плана: агент спрашивает по одному вопросу и ждёт ответа;
- ваши ответы записываются вашими словами, своё агент помечает как своё;
- агент возражает — на противоречие, на подмену задачи решением, на «да, я бы этим
  пользовался» вместо факта;
- идея по дороге может измениться, и это ход, а не сбой;
- разбор ведётся в файлах: агент заводит их сам и пишет по ходу разговора, а не выдаёт
  простыню в конце.

## Чего скил не делает

- не пишет план и не декомпозирует задачи по уже принятой идее;
- не оценивает идею вместо вас: замысел ваш, разбор общий;
- не собирает требования и не проектирует архитектуру;
- не заменяет разговор с людьми из предметки — он показывает, о чём с ними говорить.

## Установка

Скил ставится одной фразой агенту — Codex или Claude. Напишите в чате:

```
установи скил https://github.com/korshunovpro/skill-idea-funnel
```

Агент прочитает `AGENTS.md` в корне репозитория и положит папку `skills/idea-funnel/`
туда, где его среда хранит скилы. Если он не разберётся сам, дайте адрес сразу с путём:

```
установи скил https://github.com/korshunovpro/skill-idea-funnel/tree/main/skills/idea-funnel
```

Ставится папка целиком: `SKILL.md` без `PROCESS.md` и `templates/` работает, но тогда
агент ведёт записи по минимальному варианту, а не по процессу.

### То же самое руками

**Codex** — скилы лежат в `~/.codex/skills/`:

```
git clone --depth 1 https://github.com/korshunovpro/skill-idea-funnel /tmp/idea-funnel
cp -r /tmp/idea-funnel/skills/idea-funnel ~/.codex/skills/
```

**Claude Code** — личные скилы в `~/.claude/skills/`, они доступны во всех проектах;
для одного проекта — `.claude/skills/` в его корне:

```
git clone --depth 1 https://github.com/korshunovpro/skill-idea-funnel /tmp/idea-funnel
cp -r /tmp/idea-funnel/skills/idea-funnel ~/.claude/skills/
```

Claude Code подхватывает новый скил без перезапуска.

**Claude в браузере и десктопе** — скилы добавляются в настройках: Customize → Skills →
Add, загрузкой zip-архива. Внутри архива должна лежать сама папка `idea-funnel`, а не её
содержимое:

```
git clone --depth 1 https://github.com/korshunovpro/skill-idea-funnel /tmp/idea-funnel
cd /tmp/idea-funnel/skills && zip -r ~/idea-funnel.zip idea-funnel
```

### Проверка, что встало

Скажите агенту «есть идея» и опишите замысел одной фразой. Если он начинает с вопросов о
том, откуда идея и чья это боль, а не выдаёт план, — скил работает.

**Если установщик отвечает «No description found in SKILL.md».** Дело во фронтматтере:
значение `description` должно быть в двойных кавычках. Русское описание почти наверняка
содержит двоеточие с пробелом, а незакавыченное значение с таким двоеточием — невалидный
YAML. Проверить можно так:

```
python3 -c "import yaml,io;print(yaml.safe_load(io.open('skills/idea-funnel/SKILL.md',encoding='utf-8').read().split('---')[1]))"
```

## Как использовать

Отдельной команды не нужно. Агент включает скил сам, когда узнаёт в разговоре разбор
идеи; решение он принимает по описанию во фронтматтере `SKILL.md` — там же лежат и
правила срабатывания.

**Скил включается, когда:**

- вы приносите замысел — «есть идея», «набросал мысль», «раскрути», «стоит ли это
  делать», «оцени идею», «а что если сделать…»;
- надо выбрать из нескольких идей;
- вы возвращаетесь к отложенной или замороженной;
- расплывчатый замысел надо сузить;
- нужно обосновать отказ.

Слово «идея» произносить необязательно: достаточно, что вы по сути предлагаете новый
продукт, проект, сервис или направление и ждёте разбора.

**Скил не включается** на реализацию уже принятой идеи — план, декомпозиция, задачи,
архитектура. Раскрутка заканчивается решением, дальше работает другой инструмент.

**Если не сработал сам** — позовите явно: `/idea-funnel` в Claude, «используй скил
idea-funnel» в Codex. Обратное тоже верно: включился не к месту — скажите, что разбор
не нужен.

**Начинайте с одной фразы**, а не с описания на страницу: первый вопрос всё равно будет
о том, откуда идея взялась и чья это боль. Дальше — по одному вопросу за раз. Разбор
пишется в файлы по ходу разговора, поэтому его можно прервать и продолжить в другой
сессии — скажите, к какой идее возвращаетесь.

## Как менять под себя

Оба файла — обычный markdown, всё описано словами: правьте под свою практику.

Начинать стоит с `PROCESS.md`: оси скоринга и пороги — ваши, названия статусов — ваши,
состав файлов — ваш. В §7 перечислено, что можно менять смело, а что держит конструкцию
(например, уровень гипотезы рядом со скорингом: без него в работу уезжает красиво
посчитанная догадка). Уже есть свой файл процесса — скил будет вести по нему, а этот
останется лежать примером.

`SKILL.md` — метод, его правят реже и по другому поводу: когда живая раскрутка показала,
что вопроса не хватило или он задан не в том месте.

## Обратная связь

Скил вырос из живой практики разбора идей, в том числе чужих. Обратная связь и предложения
приветствуются: пишите в issues — что не сработало, где агент сорвался, какого вопроса
не хватило.
